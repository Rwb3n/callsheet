# Engineer Output Style Guide

**Status:** Active
**Scope:** TypeScript source files, test files, code comments, commit messages.
**Not in scope:** Planning documents, WORK.md files, investigation reports, interface specs — those follow `output-style.md`.
**Last updated:** 2026-02-19

---

## Governing Principle

Write the minimum code that satisfies the acceptance criteria and stays within sub-entity boundaries. Every line that doesn't exist is a line that can't be wrong.

---

## 1. Code Style

**Brevity first.** If a function body exceeds 30 lines, it does more than one thing. Extract.

**Names are load-bearing.** A good name eliminates the need for a comment. `scheduleComplianceHold` not `schedule` with a comment. Abbreviations only for universals: `id`, `url`, `ctx`, `db`.

**No defensive re-validation.** tRPC input validation is Zod's job. Drizzle types are the DB contract. Do not re-check inside a handler what Zod guarantees at the route boundary.

**Rule of three.** One use = inline. Two uses = inline. Three uses = extract a function.

**Constants, not magic numbers.** Every threshold or duration that appears more than once lives in a typed const export.

```typescript
export const ENQUIRY_RATE_LIMIT_PER_HOUR = 10
export const SCHEDULER_POLL_INTERVAL_MS = 60_000
```

## 2. TypeScript Conventions

**Strict mode always.** `"strict": true` in tsconfig. No exceptions.

**Union types over enums.** Drizzle `pgEnum` for database columns. TypeScript union for application types.

```typescript
export const verificationTierEnum = pgEnum("verification_tier", [
  "unclaimed", "claimed", "verified", "premium_verified",
])
type VerificationTier = "unclaimed" | "claimed" | "verified" | "premium_verified"
```

**`satisfies` for registry maps.** Compiler-enforced exhaustiveness.

```typescript
export const EVENT_CONSUMER_MATRIX = {
  claim_approved: [
    { consumer: "platform.searchIndex", mode: "sync" as const },
    { consumer: "operations.triage", mode: "async" as const },
  ],
} satisfies Record<EventType, ConsumerEntry[]>
```

**Export types explicitly.** `export type { Foo }` for type-only exports.

**No `any`.** Use `unknown` + narrowing. If a library forces `any`, contain it at the adapter boundary with an eslint-disable comment naming the library.

**No `as` casts.** If a type assertion is needed, the return type is wrong. Fix the type. Exception: Drizzle `$type<T>()` for JSONB columns — that is declaration, not assertion.

**`Db` type for database parameters.** Use `Db` from `@/db/types` for any function or constructor that accepts a database connection. Never import `NodePgDatabase` directly — `getTestDb()` returns `Record<string, unknown>` which is incompatible with bare `NodePgDatabase`'s `Record<string, never>` default. `Db = NodePgDatabase<any>` accepts both.

**Drizzle schema patterns:**

```typescript
id: uuid("id").primaryKey().defaultRandom(),
createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
params: jsonb("params").notNull().$type<DeferredActionParamsMap[T]>(),
senderAccountId: uuid("sender_account_id"),  // null for anonymous enquiries
```

**P4: import from owner, never copy.** [Source: shared-infrastructure.md §1.4]

```typescript
import type { ClaimApprovedEvent } from "@/lib/domains/data-and-listings/types"
```

## 3. File Organisation

```
src/
├── app/                        # Next.js pages
├── server/
│   ├── routers/                # tRPC routers — one per domain area
│   ├── procedures.ts           # publicProcedure, protectedProcedure, adminProcedure
│   └── trpc.ts                 # createTRPCContext, initTRPC
├── lib/
│   ├── events/                 # Event bus (shared infrastructure)
│   ├── scheduler/              # Deferred actions (shared infrastructure)
│   ├── flows/                  # Orchestrated flows (shared infrastructure)
│   ├── email/                  # Resend transport (shared infrastructure)
│   ├── storage/                # R2 (shared infrastructure)
│   ├── auth.ts                 # Better Auth config
│   └── constants.ts            # Typed constants
└── db/
    ├── schema/                 # One file per sub-entity + shared.ts
    ├── index.ts                # Drizzle client
    └── migrations/             # Generated by drizzle-kit
```

One router per domain area. One schema file per sub-entity. No cross-imports between schema files.

## 4. tRPC Conventions

| Procedure | When |
|---|---|
| `publicProcedure` | No auth required. Reads only. |
| `protectedProcedure` | Auth required. Any account. |
| `providerProcedure` | Auth + active listing ownership. |
| `adminProcedure` | Auth + admin role. |

**Zod schemas are exports.** Define once, import in tests. No inline re-declaration.

```typescript
export const enquirySubmitInput = z.object({
  listingId: z.string().uuid(),
  message: z.string().min(20).max(2000),
})
```

**Error codes:**

| Code | When |
|---|---|
| `BAD_REQUEST` | Business rule violation past Zod. |
| `UNAUTHORIZED` | No session. |
| `FORBIDDEN` | Session lacks permission. |
| `NOT_FOUND` | Entity absent or invisible to caller. |
| `TOO_MANY_REQUESTS` | Rate limit. |
| `CONFLICT` | State prevents operation (duplicate claim). |
| `INTERNAL_SERVER_ERROR` | Unexpected — log and surface. |

Never catch an error and return success. Throw `TRPCError` or let it propagate.

## 5. Testing

**Co-located.** `src/lib/events/bus.ts` → `src/lib/events/__tests__/bus.test.ts`.

**AC-first.** Every acceptance criterion in WORK.md has a corresponding test. Coverage metrics are a side effect, not a target.

**What to test:** Each AC. Each branch point. Each error path. Each event emission payload.

**What not to test:** Zod schema permutations. Drizzle ORM internals. Third-party library behaviour.

**Inject, don't patch.**

```typescript
interface EmailService {
  send(params: EmailSendParams): Promise<{ status: "sent" | "suppressed" }>
}
// Production: new ResendEmailService(key)
// Test: new InMemoryEmailService()
```

**Test names are assertions.** `it("rejects enquiry when listing is archived")` not `it("tests archived listing")`.

**No `beforeAll` DB setup in unit tests.** Units use injected fakes. Integration tests use a real test DB and run separately.

## 6. Comments

**Never explain what.** If you need to, rewrite the code until you don't.

**Explain why when non-obvious.** Business rules, edge cases, workarounds, constraint references.

```typescript
// Good — explains why
// null for anonymous enquiries (pre-auth buyers can submit via public form)
senderAccountId: uuid("sender_account_id"),

// Bad — explains what
// Define sender account ID column
senderAccountId: uuid("sender_account_id"),
```

**Slice references.** When a field resolves a stress test finding, annotate inline: `// [S0-4]`

**No JSDoc on internal functions.** Everything in this monolith is internal.

**No TODO in committed code.** Gaps have WORK.md tickets. Reference the ticket ID if intentional.

## 7. Module Boundaries

**Schema ownership.** `src/db/schema/data-and-listings.ts` is the only file defining D&L tables. No other schema file imports from it.

**Cross-domain reads go through query interfaces or events.** No handler in `commercial/` joins directly to a D&L table.

**Single-emitter rule.** `grep -r 'bus.emit("claim_approved"' src/` returns exactly one result. Enforced by review.

**Event bus is infrastructure, not a domain.** Import bus from `src/lib/events`. Import payload types from the owning domain's types file. Never define payload types in the bus module.

## 8. Error Handling

**Never swallow errors.** Every `catch` re-throws, wraps in `TRPCError`, or logs to `event_consumer_errors`. No empty `catch {}`.

**Async consumers: log, don't propagate.** By design (SI §1.2).

```typescript
// Async consumer
try { await doWork(payload) }
catch (err) {
  await logEventConsumerError({ eventType, consumerId, err })
}
```

**Sync consumers: log AND propagate.** The emitting request fails; user retries.

```typescript
// Sync consumer
try { await updateSearchIndex(payload) }
catch (err) {
  await logEventConsumerError({ eventType, consumerId, err })
  throw err
}
```

**Typed result unions for multi-path operations.**

```typescript
type EnquiryResult =
  | { status: "sent"; enquiryId: string }
  | { status: "queued"; pendingEnquiryId: string }
  | { status: "rejected"; reason: "SPAM" | "RATE_LIMIT" | "NOT_FOUND" }
```

---

## 9. Anti-Patterns

- **Over-commenting.** One comment per non-obvious decision, not per line.
- **God routes.** A mutation doing insert + emit + email + schedule + index update is five responsibilities. Extract each into a named function.
- **Inline `as` casts.** `(result as Foo).bar` is a type error waiting to happen.
- **Cross-boundary shared state.** No module-level variables written by two sub-entity routers.
- **Type redeclaration.** If `ClaimApprovedEvent` is authoritative in D&L types, import it.
- **`console.log` in committed code.** Use structured logging via decision log or error table.
- **Optional chaining as error suppression.** `foo?.bar?.baz` when `foo` is contractually non-null means the types are wrong.

## 10. Commit Messages

Imperative subject, ≤72 chars. Body only when the why isn't obvious from the diff.

```
Add enquiry rate limiting — 10/hour per sender

Enforces PP §5.2 spam prevention. Uses Vercel KV with
DB counter fallback.
```

Format: `{Verb} {what} [— {why}]`. Verbs: Add, Fix, Remove, Refactor, Extract, Register, Wire.

Reference spec sections (`SI §1.3`, `S6 AC-12`) not ticket IDs.

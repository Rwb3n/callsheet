# Retro: CS-WORK-029

**Date:** 2026-02-23
**Scope:** CS-WORK-029 (E2E verification workflow investigation) + spawned CS-WORK-034 (E2E harness Phase 1). Covers the investigation, principal sign-off, and work item creation.

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The Better Auth API route handler (`src/app/api/auth/[...all]/route.ts`) doesn't exist. S0 built the config (`createAuth()`) and the tRPC middleware chain, but the 5-line catch-all route that makes auth endpoints reachable over HTTP was never created. It wasn't in any work item's deliverable list. The S0 slice spec says "Better Auth handles signup natively" but the route handler that enables that was implicit, not specified. |
| **What went well?** | Verification category reclassification. Treating 7 deferred ACs as a homogeneous "E2E" bucket was the wrong frame. Splitting into 6 categories (auth HTTP, auth browser, build output, smoke test, CI meta, webhook pipeline) made the tooling decision obvious — most ACs don't need a browser at all. Also: the phased approach (API-only → browser → staging) avoids over-investing before UI exists. |
| **Could have gone better?** | The missing auth route should have been caught during CS-WORK-005 implementation. The work item's ACs (21, 22, 25) were deferred to "E2E" but the prerequisite for that E2E — the route handler — wasn't flagged as incomplete infrastructure. The E2E Debt section tracked *what needs testing* but not *what needs building before testing can happen*. |
| **Keep doing** | Investigation-first for cross-cutting infrastructure decisions. CS-WORK-029 as a separate investigation (not just "pick Playwright and go") forced the category analysis that changed the approach. The communications-infrastructure.md format precedent worked well — structured sections, options evaluation, dismissed alternatives. |
| **Stop doing** | Deferring ACs to "E2E" without specifying prerequisites. "Deferred to E2E" became a bucket that hid missing infrastructure (the auth route) behind a testing gap. |
| **Start doing** | When deferring ACs, record both "what test is missing" AND "what code is missing for the test to be writable." The E2E Debt table now has a "Phase" and "Tool" column but should also flag code prerequisites explicitly. |

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | How clean the implementation was. The spec's pseudocode in S4 §5.1/§5.2 mapped almost 1:1 to the final code. The shared `hideExcess()` / `restoreForTable()` helpers for both `mediaItems` and `credits` fell out naturally — the two tables have identical `{ id, listingId, visibility, createdAt }` column shapes. |
| **What went well?** | (1) First-pass type check had only 1 error (test helper `string` vs `"visible" | "hidden"` literal type), fixed in 30 seconds. (2) All 10 tests passed on first run against Postgres. (3) Full integration suite (312 tests) passed with zero regressions. (4) The `applyDowngrade` / `restoreHiddenItems` separation is clean — downgrade is called by webhook handlers, restore is called by tier-change consumers. No coupling between the two. (5) `suppressNotification` param from S4-ST-8 stress test finding was pre-planned in the WORK.md context — zero design ambiguity during implementation. |
| **Could have gone better?** | (1) The spec includes an event emission step (`subscription_tier_changed`) in `applyDowngrade` that the implementation deliberately omitted. The event is emitted by the webhook handler (CS-WORK-039), not by the downgrade function — the downgrade function is a side-effect called *by* the handler. This is correct but the divergence from spec pseudocode should be documented. (2) AC-24 test verifies the count query pattern directly against DB rather than through the tRPC router. A full router-level test would catch regressions in the `and()` clause wiring, but would require spinning up the storage mock and full media router deps. The query-level test is sufficient but less resilient. |
| **Keep doing** | (1) Constructor injection for deps — `ApplyDowngradeDeps` with `db` + `notificationDb` enables clean test setup with `InMemoryNotificationDb`. (2) Returning structured results (`DowngradeResult`, `RestoreHiddenResult`) — enables callers and tests to assert on exact counts without re-querying. (3) Shared table-polymorphic helpers (`hideExcess`, `restoreForTable`) using `typeof mediaItems | typeof credits` — avoids duplication across the two tables. (4) Reading the spec's exact AC wording before writing tests — each test name maps to an AC ID. |
| **Stop doing** | Nothing identified. This was a clean, well-scoped work item. |
| **Start doing** | (1) Consider adding `insertMedia` / `insertCredits` test helpers to `test-fixtures.ts` if a 2nd test file needs them (CS-WORK-039 or CS-WORK-041 likely will). Currently inline in the test file. (2) When a function deliberately diverges from spec pseudocode (e.g., omitting event emission), add a comment citing why and which work item owns the omitted step. |

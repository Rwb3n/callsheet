| **What went well?** | The work item decomposition (WORK.md) was precise — the 8 ACs mapped cleanly to two distinct implementation clusters (email prefs + closure flow, feature gate mapping) with zero ambiguity. No production `FlowDb` adapter exists — the settings router was wired with the mock pattern, deferring the Drizzle adapter. |
| **Keep doing** | Reading spec sections (SI, PP, CR) before writing code. The per-category `updateEmailPreference` mutation pattern (read → spread → update one field) was directly from S5 §10.1 and avoided the common "replace entire JSONB" mistake. Pure functions for mapping (no I/O, no side effects) — `mapFeatureAccessToUI` is trivially testable and will survive any framework change. |
| **Stop doing** | Nothing specific to this work item. |
| **Start doing** | Track `uuid` vs `text` column mismatches as a first-class tech debt item rather than noting them in retros. The `triggered_by` mismatch is a latent production bug — the flow engine will fail on closure when a production `FlowDb` adapter is created unless the column type is migrated. |

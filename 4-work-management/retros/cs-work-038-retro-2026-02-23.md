## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The spec's `finaliseSubscriptionEnd` pseudocode didn't explicitly set `subscriptionTier = "free"` on the listing — it only called `applyDowngrade()` (which hides excess media/credits) and cleared `paddleSubscriptionId`/`billingCadence`. The AC-30 test caught this: listing stayed "standard" after finalisation. The missing tier column update was an implicit assumption in the spec — the test caught what a code review wouldn't have. |
| **What went well?** | Clean session: 5 AC mapped to 3 source files + 1 test file, first-pass type check passed, 6/7 tests passed on first run (the 7th caught the real bug above). No schema migrations needed — CS-WORK-035 had already created `grace_periods` table and registered both deferred action types. The Explore sub-agent reading 19 files in one pass eliminated context-gathering overhead. |
| **Could have gone better?** | The `SubscriptionEndedEvent` type lacked `origin` and `timestamp` fields. These were in the spec pseudocode but not in the type definition (created during CS-WORK-035). Adding them was trivial and broke zero tests, but it's a gap that should have been caught during CS-WORK-035. The checkout precondition retry handler has a `refundTransaction` callback dep that's a stub — CS-WORK-040 will need to provide the real implementation, but there's no explicit AC tracking that wiring. |
| **Keep doing** | AC-first testing: writing tests that mirror ACs verbatim. The one test failure (AC-30) surfaced a genuine spec gap. Sub-agent for bulk file reading (19 files in one Explore call) — eliminated 10+ sequential reads from main context. Deps-injection pattern for all three modules — zero monkey-patching, zero module-level state. |
| **Stop doing** | Nothing new to stop. |
| **Start doing** | When expanding event payload types (like adding `origin`/`timestamp` to `SubscriptionEndedEvent`), check all existing emitters and consumers of that event type for compatibility. This time it was safe (no existing emitters), but for populated events it could break. |

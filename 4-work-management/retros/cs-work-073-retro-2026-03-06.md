# Retro: CS-WORK-073 — Event consumer implementations

**Date:** 2026-03-06
**Scope:** CS-WORK-073 (18 AC, 8 CR event consumers, S8 §10)

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The event type cascade was larger than expected. Adding `accountId` to `SubscriptionTierChangedEvent` and `subscriptionTier` to `ListingArchivedEvent` required fixing 3 emission sites in webhook-handler.ts, 1 in listing.ts, and 3 test files. The type system caught every site — no runtime surprises — but the cascade took ~15 min of the session. |
| **What went well?** | All 18 AC implemented and tested in a single pass with 0 regressions across 1440 tests. The spec's §10 pseudocode was directly translatable to implementation — almost 1:1. Splitting the old `subscription.ts` skeleton into 8 individual handler files was clean. The `TRIGGER_RESET` const shared between claim-approved and erasure-completed eliminated duplication (CR-29). |
| **Could have gone better?** | The `evaluateConversionTrigger` function in conversion-triggers.ts has a private `getEngagementCounters` that the enquiry-submitted consumer also needs. Had to inline the query in the consumer rather than importing. This is the 3rd consumer needing engagement counters (conversion-triggers, winback-evaluation, now enquiry-submitted consumer). |
| **Keep doing** | Writing all handler files before tests, then a single comprehensive test file. The handler-factory pattern (`function xxxHandler(deps): EventHandler<T>`) made every consumer structurally identical — easy to write, easy to test. |
| **Stop doing** | N/A — no ceremony failures this session. |
| **Start doing** | When adding fields to event payload types, grep for `_brand: "EventName"` immediately to identify the full cascade before writing any handler code. This session did it reactively (type check → fix) rather than proactively. |
| **Skill amendment?** | `/impl` Step 3 "Type alignment check" could explicitly include: "For each event type modification, grep all `_brand:` emission sites and list cascade files." Currently the step checks types exist but doesn't pre-map the cascade. |

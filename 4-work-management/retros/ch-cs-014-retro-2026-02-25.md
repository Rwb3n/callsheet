## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The entire chapter — 35 AC across 9 work items — completed without a single backend change. Zero new routes, zero new schema, zero new events. This validates the chapter's constraint: "consume existing backend". The S0–S6 API surface was feature-complete and all that was missing was the HTTP/client/UI wiring. The longest chain (W1→W2→W3→W5→W6, depth 5) executed without backtracking or rework. |
| **What went well?** | **Dependency graph was accurate.** The 3 independent entry points (W1, W4, W9) parallelised correctly. W7 ran alongside W5→W6→W8 with no conflicts. **Type safety was the primary guardrail.** Every page consumed exported types from routers (`ListingSummary`, `SearchResultOutput`, `ListingCardData`) — the compiler caught every shape mismatch (notably `keepPreviousData` → `placeholderData`). **shadcn primitives sufficient.** 7 base components (Button, Card, Badge, Input, Select, Table, Skeleton) covered all 4 buyer journey pages with no additional components needed. |
| **Could have gone better?** | **AC test type misclassification.** The chapter spec labelled AC-02 as "Unit" but the event bus singleton inherently requires DB — it's an integration test. The spec-writing phase should include a dependency-chain check for singletons. **Search page size.** `search-content.tsx` at ~250 lines contains `ListingCard` and `FacetGroup` as internal components. If either is needed on shortlists or saved searches, extraction is overdue. **No automated UI tests.** All Layer 3–4 AC are "Manual" test type. The E2E harness (Playwright API-only) cannot verify rendered UI. A browser-mode Playwright suite would cover AC-20 through AC-33. |
| **Keep doing** | **Reading router types before building pages.** The exported types from `search.ts`, `dashboard.ts`, and `enquiry.ts` dictated what each page could display. No guessing, no runtime surprises. **Server/client split.** Server component shell (metadata, SEO, static generation) + client content component (hooks, interactivity) is clean and keeps `"use client"` off the page-level component. |
| **Stop doing** | **Using deprecated React Query APIs from memory.** v5 changed `keepPreviousData`, `onSuccess`, `onError`, and `onSettled` — all removed from `useQuery`. Always check current API when writing hooks. **Nested landmark elements.** Root layout must use `<div>`, not `<main>`, since individual pages own their `<main>`. This was caught immediately but should be a rule, not an observation. |
| **Start doing** | **Chapter-level AC test type audit before implementation.** Walk each AC's dependency chain and verify the declared test type is reachable. Singletons that call `getDb()` cannot be unit-tested. **Rule: root layout wrapper is always `<div>`.** Pages declare their own `<main>` landmark. This avoids nested landmarks and keeps accessibility clean. **tRPC hook pattern: start from exported type, not visual design.** The router's return type is the contract — the page renders what the type provides. |

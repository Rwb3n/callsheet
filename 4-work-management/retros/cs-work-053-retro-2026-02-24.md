# Retro: CS-WORK-053

**Date:** 2026-02-24
**Scope:** CS-WORK-053 — Implement shortlist management (S6 §4, 5 AC, 20 integration tests)

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | Drizzle wraps pg errors in a `cause` chain rather than surfacing the native pg error code at the top level. `err.message` starts with `"Failed query: insert into..."` — the actual `23505` unique violation code is buried in `err.cause`. First attempt matched on `err.message.includes("unique")` which never hits. Required a recursive `isUniqueViolation()` helper traversing the cause chain. |
| **What went well?** | Schema already existed (S1 created `shortlists` + `shortlist_items` + `shortlistItemStatusEnum`). WORK.md had accurate type alignment notes — no schema surprises. 19/20 tests passed on first run. The S6-ST-1 filter design (`!= 'removed'` not `= 'active'`) was pre-specified in the slice; no design ambiguity. Router was clean CRUD with a single non-obvious concern (event emission on addItem). |
| **Could have gone better?** | The unique constraint error detection was a first-attempt failure that could have been avoided by checking Drizzle's error wrapping pattern before writing the handler. The `mediaItems` import in `shortlist.ts` is unused (imported alongside `listings` and `verifications` from the schema file). |
| **Keep doing** | Reading WORK.md type alignment section before writing code — it flagged the exact tables, enums, and event stubs needed. Starting with the smallest independent work item in a slice (053 before 051/052) as a warm-up. |
| **Stop doing** | Assuming error libraries surface native DB error codes at the top-level `message` property. Always check the wrapping pattern first. |
| **Start doing** | Adding a shared `isUniqueViolation()` or `isDatabaseError(code)` utility to `src/db/` so future routers don't need to rediscover the Drizzle error cause chain pattern. |

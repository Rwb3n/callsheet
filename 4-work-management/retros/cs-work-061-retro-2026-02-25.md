# Retro: CS-WORK-061

**Date:** 2026-02-25
**Scope:** CS-WORK-061 — Orchestrated flow and failed event admin (16 AC, S7 §6 + §7)

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | Adding `updatedAt` to `FlowRow` caused 12 type errors in existing tests and the engine's `insert` call. The fix was clean — exclude `updatedAt` from the `insert` signature since the column has `defaultNow()` — but it was a larger blast radius than expected for a single nullable field addition. |
| **What went well?** | Pre-check strategy paid off again. Reading the flow engine, adapter, bus, and schema upfront meant zero false starts. The skip constraint matrix implementation was straightforward — a static lookup object checked both in `getDetail` (for UI flags) and `skipStep` (for enforcement). Both routers implemented and tested in a single pass with only 4 test fixes needed. |
| **Could have gone better?** | The events router `oldestUnresolved` field used `sql<Date | null>` but Postgres `min()` with `FILTER` returns a string at the Drizzle level, not a Date. Same pattern as the SQL numeric→string issue from CS-WORK-059. Should have anticipated this from the open action. |
| **Keep doing** | AC-first test naming. Every test maps to an AC number, making verification trivial. Also: inserting flows via `flowDb.insert()` rather than raw SQL — tests stay type-safe and survive schema changes. |
| **Stop doing** | Nothing to stop. |
| **Start doing** | When adding a field to a shared type (like `FlowRow`), immediately grep for all `Omit<FlowRow, ...>` and direct object literal usages to assess blast radius before making the change. Would have saved one type-check round-trip. |

## 2 — Classification

| # | Item | Bucket | Detail |
|---|------|--------|--------|
| 1 | `FlowRow.updatedAt` blast radius on existing tests | Upgrade | Adding a required field to a shared type propagates to all consumers. The `insert` signature fix (exclude `updatedAt`) was the right approach — column has `defaultNow()`. |
| 2 | SQL aggregate functions return strings, not typed values | Bug | `min()`, `EXTRACT()`, `count()` via Drizzle `sql<T>` template return strings at runtime. Third occurrence (after CS-WORK-059 numeric and CS-WORK-060 count). Pattern needs documentation. |
| 3 | Skip constraint matrix as static lookup | Feature | Simple object literal with `flowType → stepName → boolean` mapping. Checked at two points: `getDetail` populates `skippable` flag, `skipStep` enforces with FORBIDDEN. No over-engineering. |
| 4 | Event retry re-emits to all consumers (not directed) | Feature | Matches spec: P2 idempotency makes directed retry unnecessary at V1 scale. Bus abstraction preserved — no per-consumer invocation exposed. |
| 5 | `InMemoryNotificationDb` doesn't clear between tests | Refactor | Module-level instance persists across test files. Worked around by filtering notifications by flowId. A `clear()` method would be cleaner. |

# Retro: CS-WORK-076 — Quality Scoring Engine

**Date:** 2026-03-07
**Scope:** CS-WORK-076 (Quality scoring engine, 21 AC, S9 Entity Intelligence)

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The `QualityScoreExplanation` type change rippled through 5 insertion sites (test-fixtures, listing creation, listing-creation, import pipeline, data-model test). All used the same `{ dimensions: {}, suggestions: [] }` zero-init shape — a single const would have prevented 5 edits. |
| **What went well?** | Pure-function-first approach paid off. 32 unit tests ran in <15ms, caught the bio double-count and freshness bucket boundary issues instantly. The enriched explanation type (array-of-dimensions with typed factors) is a strict improvement — no backward compatibility shim needed because JSONB columns accept any shape. Integration tests passed first try after fixing 3 minor issues (UUID collision, notification wording, date arithmetic). |
| **Could have gone better?** | The spec's completeness dimension lists `bio` in both mandatory and enriching categories. This ambiguity caused a scoring bug (24 not 25) that required re-reading the spec carefully. The spec's claim that "good is unreachable for unclaimed" is true for realistic seed data but not for the theoretical maximum (unclaimed + max richness = 63 = "good"). Test adjusted to use realistic seed rather than theoretical max. |
| **Keep doing** | Running `tsc --noEmit` after every type change before writing tests. The zero-error gate after the `QualityScoreExplanation` refactor caught all 5 insertion sites immediately. |
| **Stop doing** | Writing integration test assertions against notification body substrings that don't match the actual message template. The "improved"/"declined" check failed because the message said "moved from X to Y" instead. Write the notification message first, then derive the assertion. |
| **Start doing** | Defining zero-init constants for JSONB column types at the schema level (like `ZERO_INIT_EXPLANATION`). This was added during this work item but should be the default pattern for any JSONB column with a typed shape. |
| **Skill amendment?** | N/A — this is a code pattern, not a ceremony step. |

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The IMPLEMENTATION-TRACKER had CS-WORK-019 titled "Image processing pipeline (0/4)" — completely wrong. The WORK.md correctly said "Intelligent taxonomy suggestions (3 AC)". The Explore sub-agent also returned the wrong title. Tracker metadata drift is a quiet failure mode: nobody checks until you try to implement. |
| **What went well?** | Clean spec-to-code translation. S2 §9 gave exact types, exact map contents, exact query SQL. The pure function (AC-36, AC-37) separated cleanly from the DB query (AC-38), allowing 14 unit tests to run in 7ms and 4 integration tests in 463ms. Using `createTestListing` from `test-fixtures.ts` resolved it immediately. |
| **Could have gone better?** | The initial integration test was written from memory of the schema rather than reading `data-and-listings.ts` first. Two type errors caught by `tsc --noEmit` — both field name mismatches. Should have read the schema before writing the integration test helper. |
| **Keep doing** | Type check before running tests. Using `createTestListing` + `seedTaxonomy` from shared fixtures instead of inline listing creation. Keeping pure functions separate from DB-dependent functions for fast unit test feedback. |
| **Stop doing** | Guessing column names from memory. Always read the schema file when writing a new integration test helper that touches a table directly. |
| **Start doing** | Verify tracker metadata (title, AC count) against WORK.md before starting implementation. The title mismatch would have confused anyone reading the tracker without opening the WORK.md. |

# Retro: CS-WORK-020

**Date:** 2026-02-23
**Scope:** CS-WORK-020 — Image processing pipeline (S2 §4.3, 4 AC). Closes S2.

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | `ObjectStorageService` had no `download()` method. The interface was upload/delete/list only — reading back objects wasn't a use case until variant generation needed to fetch the original from R2. Small gap, but the kind of thing that only surfaces when you actually build the consumer. |
| **What went well?** | Clean separation: `naming.ts` (pure, 14 unit tests) vs `variants.ts` (side-effecting, 5 integration tests). The `ImageProcessor` injection pattern on `MediaRouterDeps` made the media router tests completely controllable — real `processListingImage`, failing stub, or absent (original S1 behaviour). No mocking sharp. Total session: plan through verification in ~20 minutes wall time. |
| **Could have gone better?** | Initial `processListingImage` was written without the try/catch (the "returns null on failure" claim in the comment didn't match the code). Caught it when writing the integration test for AC-50. Design-code consistency check should happen before writing tests, not during. |
| **Keep doing** | Constructor injection for cross-cutting behaviour (`processImage?: ImageProcessor`). Optional dep with real default — tests control it, production uses the real thing. Same pattern as `EventBus`, `SchedulerDb`, `PaymentService`. |
| **Stop doing** | Writing "best-effort: returns null on failure" in comments and then not implementing the try/catch. Comment-first is fine, but the contract stated by the comment must be immediately honoured in the implementation. |
| **Start doing** | Running the fixture-generation script inline with `node -e` instead of `npx tsx -e`. The latter silently failed (no output, no file created). `node -e` with `require('sharp')` worked first time. Minor, but wasted a round-trip. |

## 2 — Classification

| # | Item | Bucket | Detail |
|---|------|--------|--------|
| 1 | `ObjectStorageService` missing `download()` | **Feature request** | Interface was incomplete for read-back use cases. Now fixed. Any future consumer that needs to read objects back (e.g., DSAR export, image re-processing) can use `download()`. |
| 2 | Clean naming/variants separation | **Feature** | Pure functions in `naming.ts`, side-effecting processing in `variants.ts`. 14 unit tests run in 5ms. Protect this split. |
| 3 | `ImageProcessor` injection pattern | **Feature** | Optional dep on `MediaRouterDeps`. Tests inject stubs; production uses real sharp. No monkey-patching. |
| 4 | Comment-code contract mismatch (try/catch) | **Bug** | `processListingImage` stated "returns null on failure" but threw. Fixed before merge, but the mismatch was authored, not inherited. |
| 5 | `npx tsx -e` silent failure on Windows | **Refactor** | Use `node -e` with `require()` for one-off scripts involving native modules. `tsx` ESM transform + native modules on Windows is unreliable. |
| 6 | Integration test flaky timeout | **Upgrade** | `beforeEach` resetDb timeout (10s) hit on first run, passed on re-run. Pre-existing issue (noted in memory). Not caused by CS-WORK-020 changes. |
| 7 | Deliverables exceeded WORK.md plan | **Feature** | WORK.md listed 4 files. Actual: 8 files created/modified (+ test fixture). The plan didn't account for storage interface extension or media router amendment. Work items should list affected files, not just new files. |

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The implementation was unusually smooth for a 10-handler work item. Having the plan pre-written to disk (`plans/impl-plan.md`) from a prior session meant zero discovery time — jumped straight to code. The plan's type alignment section correctly predicted every helper function needed and every DB interaction pattern. |
| **What went well?** | All 21 tests (12 unit + 9 integration) passed on first or second attempt. The only failures were mock fidelity issues in unit tests (Drizzle chain mock needed `.orderBy()` support), not logic bugs. Zero type errors from the start. The existing D&L consumer patterns (`EventHandler<T>`, deps injection, `SchedulerDb` mock) transferred directly to the intelligence domain with no adaptation. |
| **Could have gone better?** | Unit test mocks for Drizzle query chains are brittle — the `contact_attempt` test needed a custom "chainable result" mock because `select().from().where()` can be either terminal (thenable → array) or intermediate (needs `.orderBy().limit()`). This pattern appears in every handler that chains DB queries differently. A shared `createChainableMockDb()` helper would reduce future test friction. |
| **Keep doing** | Pre-writing impl plans to disk for medium+ work items. The plan captured the AC-87 pre-satisfaction analysis, the uuid-vs-text audit (all clear), and the exact helper function signatures — all of which held up in implementation. |
| **Stop doing** | N/A |
| **Start doing** | For consumers that delegate to existing domain functions (like `deduplicateProfileView`, `aggregateSearchTerm`), integration tests are more valuable than unit tests with mocked DB chains. The unit test for `profile_viewed` only verifies that `db.update` was called — the integration test for the same AC would verify actual dedup behaviour. Consider defaulting to integration tests for delegation-only consumers. |
| **Skill amendment?** | N/A — this is a judgement call about test strategy, not a ceremony step. |

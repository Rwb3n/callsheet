# Retro: CS-WORK-059 — Billing Reconciliation

**Date:** 2026-02-25
**Scope:** CS-WORK-059 implementation (13 AC, billing reconciliation handler, hold expiry handler, admin billing routes, integration tests)

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | `PaymentService.listSubscriptions` took `{ paddleCustomerId }` (per-customer) but the spec's reconciliation algorithm needs ALL active subscriptions globally. Required adding `listAllActiveSubscriptions()` to the interface. The open-actions register flagged this exact risk — "confirm `PaymentService.listSubscriptions` exists before CS-WORK-059" — but the issue was scope mismatch, not existence. |
| **What went well?** | Pre-check strategy caught that all 13 ACs needed new code (0 pre-satisfied) with all infrastructure in place — schema, types, deferred action params, notification types, event reason union. Zero false starts. Admin support router (`admin/support.ts`) served as a near-perfect template for the billing router pattern. |
| **Could have gone better?** | First test run had 6 failures because single-listing test scenarios triggered the 10% anomaly threshold (1/1 = 100%). Should have reasoned about the threshold arithmetic before writing tests — every test with <10 listings and any mismatches will halt. Also hit `ConsumerEntry.consumer` type confusion (string name vs function), and `remainingHours` from SQL returning string not number. |
| **Keep doing** | Pre-check every AC before implementation. Read the spec pseudocode in full before coding. Use existing admin router as structural template. |
| **Stop doing** | Writing event bus consumer matrix entries directly in tests — the `ConsumerEntry` type is metadata (string consumer name + domain), not handler functions. Always use `eventBus.on()` for test handler registration. |
| **Start doing** | For cursor-paginated routes, decide cursor column at design time (not after test failure). UUID cursors don't correlate with `ORDER BY createdAt`. Use `createdAt`-based cursors when ordering by time. |

## 2 — Classification

| # | Item | Bucket | Detail |
|---|------|--------|--------|
| 1 | Pre-check strategy saved significant time | Feature | All infrastructure existed (schema, types, params). 0 surprises during implementation. |
| 2 | `PaymentService` interface gap: per-customer vs global list | Bug | Spec assumed global subscription listing; interface only had per-customer. Added `listAllActiveSubscriptions()`. |
| 3 | Anomaly threshold arithmetic in test design | Upgrade | Tests with 1 listing + 0 Paddle results = 100% mismatch → halt. Need ≥11 listings with ≤1 missing to stay below 10%. |
| 4 | SQL computed field returns string, not number | Bug | `EXTRACT(EPOCH FROM ...) / 3600` returns a Postgres numeric that Drizzle maps to string. Need `parseFloat()`, not `.toFixed()`. |
| 5 | Cursor pagination column mismatch | Bug | Used UUID cursor with `ORDER BY createdAt DESC`. UUID comparison doesn't match temporal ordering. Fixed to `createdAt`-based cursor. |
| 6 | `ConsumerEntry` type confusion in tests | Upgrade | `consumer` field is a string identifier, not a handler function. Test event capture requires `eventBus.on()`, not matrix injection. |
| 7 | Admin router wiring is mechanical | Feature | Adding `billing` to admin index follows exact same pattern as `support` — import, type union, router merge. No friction. |

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | Agent output quality was high — both agents produced compilable, pattern-compliant handlers on first pass. The main fixes were mechanical (idempotency skip not scheduling next run, insufficient_data output format `status` vs `reason`). No fundamental logic errors. |
| **What went well?** | 2-agent parallel delegation worked cleanly. Infrastructure-first sequencing (build shared module, then dispatch agents) eliminated the type mismatch problems seen in CS-WORK-077. Spec constants block in agent prompts prevented value drift. All 15 AC covered in a single integration test file with 15 passing tests. Total test count: 607 unit + 1009 integration, 0 regressions. |
| **Could have gone better?** | 1) Both agents missed scheduling next run on idempotency skip — had to fix 5 handlers manually. The spec says "schedule next run as final step" but agents interpreted idempotency skip as "return early without scheduling". 2) Agents used inconsistent insufficient_data output format (`reason: "insufficient_data"` vs `status: "insufficient_data"`) — spec uses `{ status: "insufficient_data" }`. Had to normalise across 5 files. 3) The `listingTaxonomyTags` table has no `tag` text column — it's a structured FK table (sectorId, serviceAreaId, specialisationId). Agent A adapted by using `zeroResultQueries` for promotable tag discovery, which is a reasonable V1 simplification but diverges from spec pseudocode that references "free-text tags". 4) AC-67 test initially failed because "steadicam operator" → "Steadicam" similarity was 0.5 (containment ratio), below the 0.8 threshold. Had to use exact match term instead. |
| **Keep doing** | Infrastructure-first sequencing before agent dispatch. Spec constants blocks in agent prompts. Reviewing every agent-produced file before moving to tests. Fixing idempotency/output format issues in bulk after all agents complete rather than interrupting them. |
| **Stop doing** | N/A |
| **Start doing** | 1) Include explicit instruction in agent prompts: "on idempotency skip, still call scheduleCeremonyNextRun before returning". 2) Include exact output format for insufficient_data in agent prompts: `outputs: { status: "insufficient_data", reason: "..." }`. 3) When spec pseudocode references a table column that doesn't exist, note the divergence in the impl plan type alignment section. |
| **Skill amendment?** | `/work-item-impl` — when building spec constants blocks for agent prompts, also include **output format constants** (e.g., insufficient_data shape) and **edge case instructions** (e.g., "always schedule next run even on early return"). These are the two most common agent drift patterns across CS-WORK-077 and CS-WORK-079. |

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | Drizzle's `sql`...`= ANY(${array})`` does not work with the `pg` driver — it passes individual positional params instead of a PostgreSQL array literal. 7 usages across the file all hit the same `op ANY/ALL (array) requires array on right side` error at runtime. `inArray()` from drizzle-orm handles this correctly and is type-safe. |
| **What went well?** | Router structure landed cleanly on first pass: 5 procedures (`query`, `suggest`, `saveSearch`, `getSavedSearches`, `deleteSavedSearch`), ranking formula, facets, sponsored placement, zero-result handling, event emission, search history. 20 integration tests written upfront and structured by AC. The 4 passing tests (autocomplete, synonyms, zero-result) diagnosed the exact failure boundary. |
| **Could have gone better?** | Two runtime bugs consumed multiple fix cycles: (1) `InProcessEventBus` constructor changed from positional args to an options object during S5, but the test file used the old `createInProcessEventBus()` factory pattern. (2) The `ANY(${array})` Drizzle/pg incompatibility. Both are "API drift" — using patterns from memory rather than checking current source. The `verificationTiers` enum cast (`string[]` vs literal union) was a third type error caught after switching to `inArray()`. |
| **Keep doing** | Writing all integration tests upfront before running them. The 4/20 → 20/20 progression gave clear signal. Using `inArray()` over raw SQL for array membership — it's type-safe and driver-portable. |
| **Stop doing** | Using `sql`...`= ANY(${expr})`` for array membership in Drizzle. It's a recurring trap with the pg driver. Always use `inArray()`. Stop relying on remembered API signatures for `InProcessEventBus` — check the actual constructor before writing test helpers. |
| **Start doing** | Before writing any test file that constructs `InProcessEventBus`, read 5 lines of a recent passing test to confirm the constructor shape. Add `inArray` to the standard import line in search/filter routers (it's as fundamental as `eq` and `and`). |

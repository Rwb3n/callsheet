# Retro: CS-WORK-052 — Implement enquiry submission

**Date:** 2026-02-24
**Scope:** CS-WORK-052. Four-branch enquiry routing (claimed/unclaimed+email/unclaimed no email/disputed), spam prevention, anonymous user support, buyer-side read routes. 8 AC, 18 integration tests, 5 files created/modified.

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The spec says Branch A routes on `claimed / verified / premium_verified` but `claim_status` pgEnum has no `verified` or `premium_verified` values — those live on the separate `verification_tier` enum in the `verifications` table. TypeScript strict mode caught this immediately via `TS2367` ("types have no overlap"). The spec conflates two distinct enums. This is the first time a spec-level enum mismatch was caught by the compiler rather than a test. |
| **What went well?** | Clean single-session execution: 8/8 AC, 18 tests, 0 type errors, 0 regressions across 41 tests in 3 files. The existing infrastructure (S5 enquiry router, S5 deferred action handler, S3 pending_enquiries table, onboarding email templates) was fully reusable — no schema migrations, no new tables, no new deferred actions. The routing logic extracted cleanly into `enquiry-routing.ts` with typed result union (`NoEmailResult | EnquiryCreatedResult`). |
| **Could have gone better?** | 1) `EnquirySubmittedEvent` type was missing `timestamp` — the spec says `enquiryId, listingId, timestamp` but the S0 placeholder type only had `enquiryId, listingId`. Required updating 3 existing consumer test files. Should have been caught during S0/S1 type population. 2) `new_enquiry` email template was defined in `EmailTemplateId` type (SI §5.2) but never registered in a production template file — only in test code. Template registration should happen at the same time as type definition. 3) Dynamic import of `user` table in initial routing module draft — unnecessary and fragile. Fixed to static import before tests ran. |
| **Keep doing** | Extracting routing/business logic into domain modules (`src/domains/platform/buyer/`) rather than inlining in tRPC handlers. The separation made the router thin (validation + delegation) and the routing module independently testable. Also: running affected consumer tests alongside new tests for regression detection. |
| **Stop doing** | Writing dynamic imports for modules that are already available as static imports. The `await import("@/db/schema/auth")` pattern was wrong — no circular dependency existed. |
| **Start doing** | When populating event payload types in S0/S1, verify every field listed in the spec's event definition (§3.5 etc.) is present in the TypeScript interface. A checklist per event type would catch `timestamp`-class omissions before downstream slices hit them. |

# Retro: CS-WORK-077 — Decay detection and enrichment scheduling

**Date:** 2026-03-07
**Scope:** CS-WORK-077 (15 AC, S9 Entity Intelligence, CH-CS-011)

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | Sub-agent worktree delegation worked better than expected — all 3 agents produced compilable, test-passing code that landed in the main working directory. The agents' file writes persisted even after worktree cleanup. The main surprise was that agent 1's detection.ts API surface differed from the planned spec (single params object vs positional args, `livenessDays` vs `livenessMs`, `ch_not_active` severity "critical" vs spec "high") — requiring ~15 min of handler adaptation. |
| **What went well?** | 3-agent parallel delegation for independent workstreams (core detection + unit tests, account-closed consumer, admin routes) completed simultaneously. The `/impl` pre-check correctly identified all type alignment points and schema column availability before coding started. The injectable `LivenessServices` pattern cleanly separated external API calls from testable logic — 18 unit tests run in <25ms. Integration tests with stub services passed first try for all 5 check types. |
| **Could have gone better?** | Agent 1 deviated from the spec's cadence values (e.g., paid email liveness 14d vs spec 7d, CH severity "critical" vs spec "high"). These deviations weren't caught until handler integration, because the unit tests tested the agent's own logic, not spec compliance. The `imdbUrl` / `imdbProfileUrl` field didn't exist on listings — agents assumed it did. Two handler type errors (`Domain` type, missing `findByDomainAndType` on mock) required manual fixing. |
| **Keep doing** | Parallel agent delegation for independent workstreams. The 3-agent split (pure logic, consumer, admin routes) had zero merge conflicts. Injectable service interfaces for external dependencies — enables deterministic testing without HTTP mocking. |
| **Stop doing** | Trusting agents to match spec values exactly without a "spec compliance" verification step. The agent produced internally consistent code, but the cadence durations drifted from the authoritative spec table. |
| **Start doing** | Include a "spec values verification" section in agent prompts for work items with numeric constants (cadence intervals, thresholds, timeout values). List the authoritative values from the spec and instruct the agent to use them verbatim. Also: instruct worktree agents to commit their changes — this was the initial assumption about why files wouldn't persist, though they actually did persist. |
| **Skill amendment?** | `/impl` skill Step 3 should add: "If delegating to sub-agents, extract all numeric constants from the spec into a typed constant block and include it in every agent prompt." This prevents per-agent drift on shared values. |

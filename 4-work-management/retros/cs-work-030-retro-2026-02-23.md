**Scope:** evaluateClaim decision engine — S3 critical path entry point. 14 AC, 28 integration tests, 5 source files + 2 type extensions.

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | The S2→S3 boundary was cleaner than expected. S2's `submitClaim` already stored `claimantAccountId` in the snapshot JSONB — the S3 spec called this out as an amendment (AC-46, S3-ST-5) but the S2 implementation had already done it. The only real S2 amendment was cancelling `pre_claim_snapshot_cleanup` before evaluation. |
| **What went well?** | 1. Clean separation of CS-WORK-030 scope (evaluation engine) from CS-WORK-031 (post-processing pipelines). The decision result types make the boundary explicit — `evaluateClaim` returns a `ClaimDecision`, the router logs it and returns the status, but doesn't execute approval/rejection effects yet. 2. Zero regressions across 385 existing tests despite rewriting `submitClaim`. 3. `acquireClaimLock` via conditional UPDATE + `.returning()` length check is clean and testable. 4. Email template registration with `hasTemplate()` guard pattern (established in S2) transferred directly — no new pattern needed. |
| **Could have gone better?** | 1. First integration run hit `decision_logs.accountId` UUID constraint — test used `"test-claimer-001"` which is not a valid UUID. This is a known pattern (in MEMORY.md) but still tripped up. 2. Second run hit FK constraint — test created a "claimed" listing with `accountId: "other-owner-id"` which doesn't exist in the `user` table. Had to seed a second user. 3. AC-43 tests used `require()` for ESM module — failed with `MODULE_NOT_FOUND`. Should have used ESM `import` from the start. All three were mechanical errors fixed in <2 minutes each but could have been avoided. |
| **Keep doing** | 1. Reading the full S3 slice spec before writing any code — the ordering constraints (dissolution before domain match), stress test fixes (S3-ST-1 through S3-ST-20), and S2 amendment notes were all critical. 2. Running `tsc --noEmit` between each source file creation. 3. Using `createUnclaimedListing` fixture with overrides for different test scenarios. 4. Upsert for snapshot (`onConflictDoUpdate`) to handle dispute path where snapshot may already exist. |
| **Stop doing** | Using `require()` in test files. ESM module system doesn't resolve `@/` path aliases via `require()`. Always use static `import`. |
| **Start doing** | 1. When a test needs a listing with a non-null `accountId`, always seed the owner user first — don't pass arbitrary string IDs. 2. Consider a `seedTestUser(db, id)` one-liner that creates user + profile in one call (currently requires `seedUsers` + `db.insert(accountProfiles)` separately). |

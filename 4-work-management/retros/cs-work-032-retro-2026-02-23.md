## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | How cleanly CS-WORK-031's `onClaimApproved`/`onClaimRejected` composed into the manual review path. `onManualReviewComplete` is essentially a thin state-guard + snapshot-read wrapper that delegates entirely to the existing pipelines. No duplication, no adaptation layer. The 030→031→032 decomposition proved well-drawn. |
| **What went well?** | (1) Single-pass implementation — no rework after first type-check. (2) The `ListingSuspendedEvent` stub was the only upstream change needed; all other types/infrastructure already existed. (3) The error-code bridging pattern (`err.code = "BAD_REQUEST"` → TRPCError) kept domain logic free of tRPC imports. (4) All 26 integration tests passed on second run (first run had one enum value bug — `"draft"` is not a valid `lifecycle_status`). |
| **Could have gone better?** | (1) Used `getSent()` instead of `getCalls()` on `InMemoryEmailService` — needed to check the actual API. This is the same class used in every prior test file; should have been muscle memory by now. (2) Used `"draft"` as a `lifecycle_status` enum value without checking the schema — the enum only has `active/inactive/merged/dissolved/suspended/archived`. (3) The `TaskSpec` type is defined locally in `manual-review.ts` rather than in a shared types file. If CS-WORK-033 (verification upgrade) needs it, it'll import from the claim module, which is architecturally odd. |
| **Keep doing** | (1) Type-checking before running tests — catches 90% of issues in seconds. (2) Writing TaskSpec builders as pure functions with no DB deps — trivially unit-testable. (3) Keeping domain logic error codes separate from transport layer (tRPC). (4) Using `createUnclaimedListing()` + override pattern for test fixture setup. |
| **Stop doing** | (1) Guessing enum values — always check the Drizzle schema before using an enum value in tests. |
| **Start doing** | (1) Extract `TaskSpec` type to a shared location (`src/domains/operations/types.ts` or similar) before CS-WORK-033. S7 will definitely need it too. (2) Consider a `test-api-cheatsheet.md` or similar — a quick reference for `InMemoryEmailService.getCalls()`, `InMemoryNotificationDb.getAll()`, `ActionHandlerRegistry.get()` cast patterns. These come up every work item. |

# Retro: CS-WORK-034

**Date:** 2026-02-24
**Scope:** CS-WORK-034 — E2E verification harness Phase 1 (API-level). 7 AC, Playwright API-only, Better Auth route handler, test endpoints, CI integration.

---

## 1 — Reflection

| Prompt | Notes |
|--------|-------|
| **What surprised you?** | Three runtime issues not anticipated by the investigation or readiness check: (1) Better Auth throws on default secret in production mode (`next start` always sets `NODE_ENV=production`), (2) CSRF `Origin` header required by Better Auth's `formCsrfMiddleware` — Playwright `APIRequestContext` doesn't set it, (3) `email_verification` template not registered at runtime (only in tests). The investigation identified the right tool (Playwright API-only) and the right architecture (reset endpoint, cookie jar) but didn't surface these three integration-level blockers. |
| **What went well?** | Investigation brief (CS-WORK-029) correctly scoped the work — all 7 ACs were achievable in a single session without scope changes. Playwright API-only mode worked exactly as advertised: no browser binaries, full cookie jar, `webServer` config handles build+start lifecycle. The `InMemoryEmailService` capture pattern enabled verification URL extraction without a real email provider. Existing `resetDb()` was reusable with minimal refactoring (extract constant). |
| **Could have gone better?** | Three debug-fix cycles during E2E test execution: (1) BETTER_AUTH_SECRET missing → add to .env.local, (2) template unregistered → add auth-instance.ts with template registration, (3) CSRF Origin header → add `extraHTTPHeaders` to Playwright config. Each required a rebuild (20s) + test run. Total debugging time was ~15 minutes across 3 cycles. A pre-flight checklist checking "can the auth route handler actually process a signup request?" would have caught all three before writing tests. |
| **Keep doing** | Readiness checks before starting work items — the table at the start caught the missing auth route, empty e2e directory, and placeholder `createProductionServices()`. Running unit + integration tests after each structural change to catch regressions immediately. |
| **Stop doing** | Writing the AC-03 guard as `NODE_ENV !== 'production'` when `next start` always sets production mode. The investigation said "NODE_ENV guard" but didn't account for the Next.js production-mode constraint. Should have caught this during investigation. |
| **Start doing** | For any work item that creates a new HTTP route handler, add a "smoke request" step to the implementation plan: build, start, curl the endpoint, verify 200 before writing tests. This would have surfaced the BETTER_AUTH_SECRET and template registration issues immediately. |

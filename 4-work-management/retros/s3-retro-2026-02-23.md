The whole slice completed in one session despite 48 AC, because the dependency chain was so well-drawn that each work item was incremental. |
| **What went well?** | (1) **Single-session slice completion.** 4 work items, 48 AC, 79 new tests, zero regressions across 479 total tests. (2) **S0/S1/S2 infrastructure held.** Event bus, scheduler, decision logging, email service, notification system — all composed without friction. | **Could have gone better?** | (1) **Recurring test fixture bugs.** Three work items hit the same class of error: wrong method name (`getSent` vs `getCalls`), invalid enum value (`"draft"` not in `lifecycle_status`), wrong credit format enum (`"feature_film"` vs `"feature"`). This is the 2nd occurrence (also in CS-WORK-017). Not blocking but erodes trust in generated deliverable lists. (3) **`ClaimRouterDeps` is at 8 fields.** Flat bag is still manageable but starting to feel heavy. Kept flat per "rule of three" (only 1 consumer), but S7's admin routes will likely be the trigger. |
| **Keep doing** | (1) Thorough codebase exploration before writing any code — reading every relevant file via Task/Explore agent. (2) Type-checking between each source file creation. (3) Writing domain functions as standalone units with injected deps, testing directly, testing the router only for transport-level concerns. (4) Resolving retro action items within the same session when context is fresh. (5) Pure-function TaskSpec builders — zero DB deps, trivially testable. |
| **Stop doing** | (1) Guessing enum values or test utility method names. Always check the Drizzle schema `pgEnum` and `InMemoryEmailService` class definition before writing test code. (Already added to memory as cheatsheet.) |
| **Start doing** | (1) **Template registration audit** — grep `EmailTemplateId` union against `registerTemplate` calls at slice completion. Any type without a registration is a latent runtime crash. (2) **S4 decomposition** should account for the `subscription_ended` handler's high cross-domain complexity (memory notes it as the highest accumulation across S7/S8/S9). Plan work item boundaries around it. (3) Consider if the verification router should be added to the main app router — currently it's a standalone `createVerificationRouter` factory but isn't wired into any root router. This is consistent with how all other routers work (S7 wires them), but worth noting. |
